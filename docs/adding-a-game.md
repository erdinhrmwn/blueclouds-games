# Adding a game

1. Server: add `apps/server/src/games/<slug>/` with its actor and rules, and register the actor in `registry.ts` as `<slug><Entity>` in camelCase, named after what one instance holds (`bust31Room`: one table, keyed by room code; never an `Actor` suffix, and never renamed once live), with `options: { name, icon }` for the Rivet dashboard. Seats, the turn clock, leaving, the room list, the move log, the match result outbox and tournament tables come from `games/shared/`; the room reports to `roomList` under its slug. For tournaments, copy what both existing actors do: `wakeTournament` in `onWake`, `seatFor` and `tournamentTick` in `join`, `requireOpenTable` in the host actions, a `tournamentStart` action, and `tournament: tournamentView(c)` in the view.
2. Web: add `apps/web/src/lib/games/<slug>/` with a `Home` (include `<Tournaments>`) and `Room` component, add an entry to `catalog.ts`, and map the slug to its room actor in `lib/server/rivet.ts`. The table renders on a fixed-size stage (`Stage.svelte`, 1280x720 on landscape windows, 390x780 on portrait ones, scaled to fit): style it with `wide:` and `tall:` instead of `sm:` (dialogs keep `sm:`, they are not scaled), give the felt's wrapper `min-h-0 flex-1` and everything under it `shrink-0`, and pass on-screen distances through `unscaled()` from `lib/stage.svelte.ts` before using them in a transform.
3. Platform: add a migration that inserts the game into `games` (slug, name, seat limits, and what its per-seat `score` means), so match results are accepted. No other platform or backoffice change is needed ([match-schema.md](architecture/match-schema.md)).
4. Move log: every match must send its full move log with the result ([match-log.md](architecture/match-log.md)). Derive the events in the game's `match.ts`, list them in its `rules.md`, and optionally add a backoffice renderer in `apps/backoffice/src/lib/games/<slug>.ts` (register it in `lib/replay.ts`); without one the backoffice shows the raw events.
5. Docs: add `docs/games/<slug>/rules.md` (and `design.md` if the game has its own UI reasoning), and list it in the README.
